# PROJECT RULES — Breus Media Web Development & Audit Standards

Официальный свод обязательных правил и регламентов разработки, аудита, копирайтинга и деплоя проекта `breus.media`.

---

## 1. Валидация контента в шторках (SSR vs Client Mount)

- **Требование поисковых роботов**: Поисковые системы и поисковые нейросети (SearchGPT, Googlebot, Perplexity, Claude) должны видеть весь текст услуг, цен и офферов в первичном HTML-ответе сервера Next.js.
- **СТРОГИЙ ЗАПРЕТ**: Запрещено использовать динамический клиентский рендер вида `{isOpen && <Content />}`, если контент не дублируется в исходном HTML-коде.
- **Решение**: Контент шторок, аккордеонов и выпадающих меню обязан находиться в начальном DOM (например, быть скрыт через классы CSS/Tailwind `hidden`/opacity или семантические теги `<details>`), чтобы краулеры индексировали его без необходимости клика или выполнения JS.
- **Обязательный тест верификации**:
  ```bash
  curl -s [URL_СТРАНИЦЫ] | grep "[Ключевая фраза из шторки]"
  ```

---

## 2. Предпросмотр через Vercel Preview (вместо Localhost)

- **Требование к тестированию**: Все сравнительные тесты («Было» vs «Стало») делаются исключительно через Vercel Preview Deployments, чтобы страница могла тестироваться на реальных смартфонах (Safari и Chrome на iOS, Chrome на Android) вне домашней Wi-Fi сети.
- **Формат выдачи результатов**: При подготовке любых доработок агент собирает Preview-ветку и предоставляет Антону ровно 2 живые ссылки:
  * 🔗 **Ссылка №1 (Было)**: текущий прод/превью исходной версии страницы.
  * 🔗 **Ссылка №2 (Стало)**: превью-деплой с внедренными правками v3.0.

---

## 3. Фильтр «Лексическая однозначность»

Перед любым изменением текста, заголовков или описаний обязательно проверять термины на отсутствие двойного дна, размытых абстракций и ложных ожиданий:
- Запрещены слова вроде «площадки» без конкретного контекста («веб, карты, соцсети»).
- Запрещены фразы вроде «хостинг включен» без точного указания срока и условий.
- Запрещены формулировки вроде «любые форматы» без исчерпывающего перечня деливерейблов.
- Полное соблюдение редполитики Zero Fluff: запрет пустых слов-паразитов («уникальный», «лучший», «профессиональный», «под ключ», «сырые файлы»).

---

## 4. Шлюз согласования текста перед коммитом (Human-in-the-Loop Gateway)

**СТРОГО ЗАПРЕЩЕНО** делать `git commit` и `vercel deploy` любых правок в копирайтинге, офферах, тарифах, ценах в GEL и FAQ без предварительного согласования в диалоге!

Обязательный регламент:
1. Вывести Антону сравнительную таблицу:
   | Файл / Блок | Было | Предлагаемый текст (Стало) | Обоснование однозначности |
2. Дождаться прямого подтверждения («ОК / Согласовано») от Антона в диалоге.
3. Только после получения одобрения вносить правки в git и собирать/деплоить.

---

## 5. Регламент сборки и деплоя

- Никогда не пушить и не деплоить в production без явной команды пользователя `DEPLOY NOW`.
- Перед любым деплоем обязательно прогонять проверку сборки:
  ```bash
  NEXT_PUBLIC_DEBUG_MODE=false npm run build
  ```
  Сборка обязана завершаться со статусом 0 ошибок.
- После внесения изменений синхронизировать записи в `CONTEXT_NEXT_CHAT.md` и `CHANGELOG_ARCHIVE.md`.

---

## 6. Полная заморозка основного домена (Production Freeze)

- **Основной production-домен `breus.media` СТРОГО ЗАМОРОЖЕН**: домен не трогаем до тех пор, пока Антон не примет весь сайт целиком в готовом виде.
- Запрещены любые автоматические или ручные обновления продакшена (`git push origin main` с триггером прод-деплоя или `npx vercel --prod`).
- **Все итерации, тесты и демонстрации ведутся ИСКЛЮЧИТЕЛЬНО через Vercel Preview Deployments** (`npx vercel deploy -y`).
- Выкатка на боевой домен допускается только после завершения всех страниц и получения прямой команды от Антона:
  ```text
  DEPLOY NOW
  ```

---

## 7. Единый реестр версий страниц (Page Version Registry)

Каждая итерация и доработка любой страницы обязана маркироваться строгим кодом версии и заноситься в `site-docs/PAGE_VERSION_REGISTRY.md`.

- **Формат идентификатора**: `[PAGE_CODE]-V[X.Y]` (например: `DRONE-V1.0`, `DRONE-V2.0`, `DRONE-V3.0`, `TOUR360-V1.0`, `REELS-V1.0`).
- **Обязательные поля в реестре для каждой версии**:
  * **Код версии**: уникальный ключ.
  * **Живая ссылка Vercel Preview**: постоянная ссылка для полевого теста на смартфонах.
  * **Статус**: `Архив (Было)` | `На ревью (Стало)` | `Утверждено` | `Отклонено`.
  * **Архитектурный профиль**: параметры Hero (скорость, заголовок, текст), организация услуг (сетка, табы, фильтры), тарифы (вертикаль, свайп, аккордеон), конверсионный слой.
  * **Оценка аудита**: балл по 30-факторной системе.
- **Принцип обратимости**: Антон в любой момент может назвать код версии (например: *«Мне нравится DRONE-V2.0, но фильтры возьми из V3.0»*), и агент обязан восстановить точную конфигурацию без путаницы и потери контекста.

## 8. Принцип «Айсберга» (Visual Simplicity vs Deep SSR Grounding)

- **Пропорция внимания (10% на поверхности / 90% под водой)**: 
  * Первый экран (Hero) отдается строго под «правило 3-х секунд» и человеческое восприятие (Apple / Linear standard): лаконичный H1, 2 строки оффера, кинематографичный визуал и прямой CTA. Запрещено перегружать первый экран техническими характеристиками, длинными перечнями оборудования и монотонным текстом.
  * Вся тяжелая 30-факторная доказательная база (лицензии GCAA, подробные техтребования 4K HDR, GPS-привязка к районам Тбилиси и Батуми, регламенты выезда, условия согласования, полная спецификация деливерейблов) уходит в нижнюю треть страницы.
- **Техническая реализация**: 
  * Вся скрытая фактура обязана находиться в первичном серверном HTML через нативные теги `<details className="group">` или структурированные таблицы с классом доступности, обеспечивая 100% видимость для краулеров (SearchGPT, Googlebot, Perplexity) без создания визуального шума для мобильного пользователя.

---

## 9. Архитектура двухконтурного роутинга (Brand Flow vs Search Intent)

В проекте строго разделяются два входящих пользовательских потока:

1. **Брендовый / Внутренний поток (L1 Homepage Flow)**:
   * Главная витрина (`/gazeta` или `/`) решает задачу первого знакомства, позиционирования и выбора направления.
   * Навигация строится по принципу: **Главная L1 ➔ Отраслевые витрины (Индустрии: Недвижимость, Отели, Рестораны, Авто, Клиники)** через интерактивные шторки (Drawer) и чипы категорий.

2. **Органический / Поисковый поток (L3 Monolith SEO Flow)**:
   * Поисковый трафик из поисковых систем (Google, SearchGPT, Perplexity, Яндекс, Карты) приземляется **напрямую на глубокие автономные монолиты L3** (например: `/drone-services/drone-real-estate`, `/360-tour-hotels`, `/drone-services/drone-restaurants`).
   * Каждая страница L3 проектируется как самодостаточный, полноформатный конвертер в сделку: с жесткой нишевой юнит-экономикой, ценами в GEL, калькулятором ROI, локальными гео-якорями и прямым выходом в WhatsApp за 24–48 часов, минуя необходимость возвращаться на главную.
